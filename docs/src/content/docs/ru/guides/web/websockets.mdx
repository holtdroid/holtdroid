**Зачем:** чаты, живые цены и статусы заказов приходят через WebSocket, а не обычными запросами, поэтому в списке
Network их не видно. Эта вкладка их показывает — вместе с тем самым сообщением, после которого появился баг.

<Guide id="websockets" />

## Что происходит

1. Откройте вкладку <Hint to="tab-websockets" step={1}>WebSockets</Hint>. **WebSocket** — это соединение, которое
   остаётся открытым, чтобы сервер мог присылать обновления в любой момент.
2. Каждая строка — <Hint to="frame-hello" step={2}>одно сообщение</Hint>: стрелка вверх — его отправило
   приложение, стрелка вниз — оно пришло с сервера; рядом длина и время.
3. Нажмите на сообщение, например на <Hint to="frame-price" step={3}>обновление цены</Hint>, чтобы прочитать его
   <Hint to="frame-details" step={4}>
     целиком
   </Hint>
   .
4. Ищите сообщение прямо перед поломкой: здесь <Hint to="frame-order" step={5}>заказ</Hint> не прошёл с
   `out_of_stock`, а приложение ничего не сказало пользователю.

## Полезно знать

- Вкладка работает и без открытого DevTools.
- Holtdroid хранит трафик сокетов с момента запуска приложения, поэтому вкладка покажет всё, даже если
  перезагрузить страницу портала или открыть сессию на другом компьютере.
- **Clear** очищает список только в вашем браузере. **Hide under 15 B** прячет пинги и другие крошечные сообщения.
  Пауза останавливает список; после продолжения дописывается то, что пришло за это время.
- Event streams (ещё один способ, которым сервер присылает обновления) тоже видны здесь.
- Пока сессия записывается, нажмите на время сообщения, чтобы поставить в этот момент маркер на записи.

## Если не работает

- **Список пустой**: страница ещё не открыла сокет. Откройте ту часть приложения, где есть живые данные.
- **Сокет помечен как видео, и сообщений нет**: видеопотоки специально не показываются, иначе они завалили бы
  список.

Подробнее: [WebView DevTools](/holtdroid/ru/concepts/devtools/).
