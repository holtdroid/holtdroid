**Навіщо:** ви робите веб-частину застосунку на ноутбуці й хочете побачити її всередині WebView справжнього
застосунку на справжньому Android, нічого не викладаючи на сервер.

<Guide id="local-server" />

## Що відбувається

1. Спершу [підключіть свій комп'ютер](/uk/guides/developers/connect-computer/) і не закривайте клієнт
   `holtdroid`.
2. <Hint to="terminal" step={1}>Запустіть dev-сервер</Hint>
   як зазвичай, наприклад Vite на порту 5173.
3. Порт з'явиться на сторінці Computers. <Hint to="port-5173" step={3}>Клацніть по ньому</Hint>, щоб опублікувати
   його на своїх пристроях; у режимі **Dev servers** (він типовий) клієнт публікує сервери на кшталт `node`, `bun`
   чи `vite` сам.
4. На сторінці сесії <Hint to="w-ssh" step={6}>картка SSH</Hint> показує <Hint to="ssh-port-5173" step={7}>опубліковані порти</Hint>.
5. Відкрийте на телефоні <Hint to="phone" step={8}>`http://localhost:5173`</Hint>: сторінка приходить з вашого
   ноутбука.

## Варто знати

- Порт — це «номер дверей», біля яких програма чекає на підключення: dev-сервер слухає 5173, тому він
  `localhost:5173`. Публікація відчиняє такі самі двері на пристрої.
- Опублікований порт потрапляє на всі ваші пристрої, зокрема ті, що ви запустите пізніше, і лише на ваші.
- Звичайний `http://localhost` працює, навіть якщо застосунок забороняє незашифрований трафік: для localhost
  Android робить виняток. Решта адрес підкоряється правилам застосунку.
- Гаряче перезавантаження працює: зберегли файл — сторінка на телефоні оновилася.
- У режимі **Everything** публікується все, що слухає порти на вашому комп'ютері, включно зі звичайними програмами.
  Клієнт питає, перш ніж увімкнути цей режим.

## Якщо не працює

- **Порту немає на сторінці Computers**: перевірте, що клієнт запущено, а сервер слухає `localhost`, а не лише якусь
  іншу адресу.
- **Порт у картці SSH червоний**: на цьому порту вашого комп'ютера ніхто не відповідає. Запустіть сервер або
  перевірте номер.
- **Сторінка відкривається, але запити до API падають**: застосунок досі звертається до API за звичайною адресою.
  Спрямуйте і його на `localhost` або опублікуйте ще й порт API.
- **На емуляторі порт пропускається**: кілька портів зайняті самою сесією (5555, 5038, 27042, 18580, 18581, 7890,
  9090). Візьміть інший.
